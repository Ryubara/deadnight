# Permanent progression

What grows between nights, how it is earned, what it unlocks and when, and what the platform backend stores. This
page is a design: nothing here is built, every number is a first guess in one table each, and the questions only the
maintainer can answer are at the end.

## In one paragraph

A night is a fresh start and stays one: the same points, the same fuel, the same lot for everybody. What carries over is
**breadth, identity and know-how, never strength**. Playing earns *Billing* (an account level whose rewards widen the
choices a player brings to the night), *weapon mastery* (which unlocks side-grade *trims* for the weapons they use),
*Concession Orders* (goals that reward lighting the lot, holding it and rescuing each other), *daily challenges* and
*milestones* (small goals that turn a night into a few good reasons to play it) and *stubs* (a currency that buys only
cosmetics). Missing a day costs nothing but that day's three, nothing is sold that changes a night, and a level-1
player and a level-50 player can stand in the same lot and be equally dangerous.

## What the research says

Study was for understanding only; no name, number or presentation below is ours to reuse. Forum threads are named as
anecdotal where they carry the claim. Several press pages could not be read in full by the tooling; those rows lean
on the search summary and are marked.

| Approach (example) | What it does | Works | Backfires | Take for Deadnight |
| --- | --- | --- | --- | --- |

| Class levels with a free track, cosmetic-only money (Deep Rock Galactic) | Per-class levels, a free seasonal track, paid items are cosmetic | A free progression track "grafts well" onto existing progression ([Game Rant](https://gamerant.com/deep-rock-galactic-interview-season-1-co-op-design-battle-pass-progression/), [season FAQ](https://www.deeprockgalactic.com/season01-faq)); when fans objected that a paid cosmetic's original design was free for everyone, the studio moved the original into the free track ([PC Gamer](https://www.pcgamer.com/deep-rock-galactic-studio-remakes-cosmetic-dlc-after-fans-complain-everyone-gets-the-original-designs-for-free)) | Anecdotal: little to do beyond 10-20 hours except cosmetic farming ([Steam thread](https://steamcommunity.com/app/548430/discussions/1/3492005739867760090)) | Money, if ever, only buys cosmetics; the plain version of every cosmetic stays earnable |

After the cap the track keeps going without taking anything away |
| Weapon camo and mastery tracks (Call of Duty Zombies) | Each weapon has tiered challenges for camos | Goals tied to the weapon you already like | Players call the grind too long and say certain weapon archetypes are always better ([Gamereactor](https://www.gamereactor.eu/what-really-grinds-my-gears-call-of-duty-black-ops-6s-camo-challenges-1453823/)); challenge bugs ([NME](https://www.nme.com/news/call-of-duty-vanguard-players-report-weapon-challenges-are-bugged-3088522)) | Few mastery tiers, reachable in a handful of nights, rewarded with side-grades that make the weapon *different*, not better |
| Challenge-only battle pass (Halo Infinite) | Pass progress only from challenges at launch | Clear goals | Backlash that matches did not count; the studio added "play 1 game" challenges and sped weekly ones up ([GameSpot](https://www.gamespot.com/articles/halo-infinite-major-battle-pass-progression-changes-coming-this-week/1100-6498137/), [Windows Central](https://www.windowscentral.com/halo-infinite-fans-angry-about-battle-pass)) | Playing the game always earns; challenges add to it, never replace it |
| Permanent, un-expiring tracks (Helldivers 2 warbonds) | Premium tracks never retire; premium tracks can be progressed with medals earned in play | Studio statements that they never retire and are not pay-to-win ([Prima Games](https://primagames.com/tips/do-helldivers-2s-warbonds-go-away-answered), [Yahoo](https://www.yahoo.com/tech/helldivers-2-warbonds-not-pay-220436504.html)); a limited-run crossover was made permanent ([Final Boss](https://finalboss.io/helldivers-2-x-killzone-is-back-this-time)) | Premium tracks still cost paid credits | Nothing expires; a returning player picks up where they left off |
| Expiring seasons and daily tasks (battle passes in general) | Rewards vanish when the season ends | Predictable revenue (not our concern) | FOMO and burnout; even a never-expiring pass can create FOMO through a purchase window ([VideoGamer](https://www.videogamer.com/features/marvel-rivals-battle-pass-still-gives-players-massive-fomo-and-it-should-be-fixed), [Exputer](https://exputer.com/features/battle-passes-replaced-loot-boxes-consumers/)); commentary, not data | No timers on lasting progress and no streaks. | Random loot and crafting (Vermintide 2, Darktide, Killing Floor 3) | Gear power from chests and crafting | Vermintide 2's designers wanted gear to matter less than skill ([PC Gamer](https://www.pcgamer.com/how-warhammer-vermintide-2-plans-to-fix-the-first-games-loot-system), via search summary) | Darktide's launch progression was called RNG-heavy and incomplete, and Fatshark apologised and rebuilt it ([Shacknews](https://shacknews.com/article/133824/warhammer-40000-darktide-launch-apology), [PC Gamer](https://pcgamer.com/fatshark-details-upcoming-changes-to-darktides-gear-acquisition-and-crafting)); Vermintide 2 players report a slow power grind and an account-wide item level that leaves alts behind (anecdotal); Killing Floor 3 launched "Mixed" with a progression grind, worse solo ([MeinMMO](https://mein-mmo.de/en/killing-floor-3-launch-durchwachsen,1516766)) | No random power. Every unlock is a named thing the player picked or earned |
| Meta currency that pays on failure (Vampire Survivors, Hades) | Every run, won or lost, pays toward permanent options | "Players always have something to work towards, even when they don't manage to complete a run" ([Substack](https://jboger.substack.com/p/the-secret-sauce-of-vampire-survivors), community analysis); opt-in difficulty for opt-in reward ([fan analysis](https://saschb2b.github.io/game-mechanics/games/hades/meta-progression)) | - | A lost night pays almost the same; harder nights are a choice that pays more |
| Unlocks that add options (Risk of Rain 2) | Challenges unlock characters, skills, skins; items reset every run | Unlocks "have entirely different experiences" rather than raise power ([PC Gamer](https://www.pcgamer.com/au/risk-of-rain-2-character-unlocks), [GamesRadar](https://www.gamesradar.com/risk-of-rain-2-challenges)) | Some challenges needed rework (anecdotal) | The model for the whole page |
| No persistent power (Left 4 Dead) | The Director varies each run; player strength does not carry | The Director decides where items and threats appear, so levels replay differently ([Valve design theory](https://developer.valvesoftware.com/wiki/Left_4_Dead_Design_Theory)); we found no source on why it skips unlocks | Nothing to collect between sessions (our reading) | Deadnight's rounds supply the variation; progression supplies the collecting |
| Always-online progression (Payday 3) | Progression needs the servers | Cross-progression | Launch outages kept players out; Starbreeze found update-pipeline errors that could have wiped progression ([GameSpot](https://www.gamespot.com/articles/payday-3-devs-ceo-apologizes-for-online-shooters-unstable-launch/1100-6517936/), [mp1st](https://mp1st.com/news/payday-3-first-patch-issues-identified-before-it-can-be-released-starbreeze-revamping-patching-process-for-steady-cadence)) | A night never waits on the backend; rewards queue and are replayed safely |
| Level as a matchmaking signal | Match or filter by account level | Easy to build | Level is a weak proxy for skill: farmed XP, smurfs, several characters ([EA forum threads](https://forums.ea.com/discussions/star-wars-battlefront-2-en/the-matchmaking-balance-thread/10839464/replies/10839533), anecdotal); newcomers say veteran lobbies push them out | Never match on level; make level harmless instead |

The motivation underneath, from self-determination theory applied to games: the pull of a game comes from
**autonomy, competence and relatedness**, and in multiplayer games all three independently predict enjoyment and
continued play ([Ryan, Rigby and Przybylski 2006](https://link.springer.com/content/pdf/10.1007%2Fs11031-006-9051-8.pdf)).
That is the test for every feature below: it should give a choice (autonomy), a visible sign of getting better
(competence) or a reason to play with other people (relatedness) - and a number going up is only the weakest of the three.

## Rules we hold ourselves to

| # | Rule | Because |
| --- | --- | --- |
| 1 | **The night resets.** Starting points, fuel, circuits and the lot are the same for every player. Permanent data never raises a number in the rounds, economy or fuel tuning | Power creep and split lobbies; Vermintide 2's designers said they wanted gear to matter less than skill (research table) |
| 2 | **Unlocks widen, they do not raise.** Every unlocked thing is a side-grade of something every player already has, priced the same, and it changes a decision | Rule-changing beats stat-changing; old and new players stay in one balance |
| 3 | **One gate per item.** An item is earned by exactly one of: a Billing level, a mastery level, a named order, or stubs. Never two in series | Stacked gates are what players call grind |
| 4 | **Stubs buy cosmetics only.** Anything that changes a night cannot be bought, rerolled, skipped or boosted with any currency | Keeps pay-to-win off the table before the money question is even asked |
| 5 | **Playing always pays.** Win or lose, solo or four, a night earns; challenges add to it | Halo's lesson, Back 4 Blood's lesson |
| 6 | **A missed day owes nothing.** Daily challenges exist and expire at each daily reset, finished or not (the maintainer, 2026-11-02, [decision](#decision-daily-challenges)): no banking, no carry-over, no streak, no login reward, nothing for a missed day. Orders and milestones have no timer and never expire, and no item or reward exists only on one date | FOMO and burnout; a daily is an offer for one day, never a debt |
| 7 | **No random power.** Randomness in a night (the crane) is fine; randomness in what a player *has* is not | Darktide, Vermintide |
| 8 | **Level never sorts people.** No matchmaking, no difficulty, no lock on level | Weak signal; and most lobbies here are friends |
| 9 | **The server awards, the client asks.** Only an authoritative game server instance started by the platform can report a result | Cheating and trust; the game is network-first, with an authoritative server |
| 10 | **A night never waits on the backend.** Rewards are reports that can be late, never a condition to play | Payday 3 |

## What grows

| Layer | What it is | Gives | Gate | Resets |
| --- | --- | --- | --- | --- |
| **Billing** | The account level, 1 to 50, then Encores | A wider choice pool: more crane and wall weapons, more tonics, sidearms, flashlights, lobby options; milestone cosmetics | Night XP | never |
| **Mastery** | A level 1 to 10 for each weapon | Finishes and two trims (side-grade variants) for that weapon | Points earned with it | never |
| **Concession Orders** | Three active goals at a time | XP, stubs, and named cosmetics for finished families | Doing the thing | a finished order is replaced; progress on an open one stays |
| **Stubs** | The cosmetic currency | Costumes, finishes, marquee pieces, screen reels, horn and emotes | Night XP (one stub per five) and orders | never |
| **The Cast and the Marquee** | What others see: costume, name plate, frame, bulbs | Identity | Stubs, Billing milestones, orders | never |
| **Encore** | Levels after 50 | Cosmetic frames and marquee bulbs only; takes nothing away | Night XP | never |

### Billing (account level)

A drive-in sells you a place in a billing: the **Marquee** is the account's sign, and each level lights one more bulb.
Ten levels make a tier, named for how a night at the pictures is billed.

| Levels | Tier | Meaning in play |
| --- | --- | --- |
| 1-9 | Newsreel | The starter program is small on purpose: the first nights are about the lot, the light and each other |
| 10-19 | Short Subject | The pool opens: new weapons, tonics, flashlights |
| 20-29 | Second Feature | Opt-in difficulty and the weekly bill |
| 30-39 | Main Feature | Cosmetic milestones and the second marquee frame |
| 40-50 | Headliner | The long tail; the last tier is cosmetics |
| 51+ | Encore | A bulb or frame for each level; nothing resets |

XP to go from level L to L+1 is `150 + 30 x L`: 180 for the first, 1,620 for the last, 44,100 in all. The curve is a
function in code and only raw XP is stored, so retuning it needs no data migration.

The **starter program** is the small, complete set every new player has and every veteran can always fall back on.
It is what the in-review rounds tuning already sells: the crane pool of shotgun, rifle, submachine gun, flare gun,
baseball bat and fire axe,
the four tonics (second wind, hearty, quick hands, fleet) and the sidearm. The rounds work chooses these items; this page
only decides *when the rest arrive* (see [first ten hours](#first-ten-hours-a-tuning-table)).

| Billing level | Unlocks (pool breadth) |

| 2 | Three Concession Order slots |
| 4 | A second sidearm (a different handling, not a better one) |
| 6 | One more weapon in the crane pool |

### Mastery and trims

Each weapon carries its own level, 1 to 10, from the points a player earns with it (one mastery point per 25 points
of the economy, capped at 500 a night per weapon so one night cannot finish one). Level N to N+1 costs `400 + 100 x N`,
8,100 in all. The crane gives random weapons, so mastery rewards using whatever you are holding, not hoarding one gun.

| Mastery level | Reward |
| --- | --- |
| 2 | First finish (paint) |
| 3 | **Trim B**, a side-grade |
| 6 | **Trim C**, a second side-grade |
| 10 | Mastery finish (a showpiece look) |

A **trim** is chosen before a night, one per weapon, and it must meet the *side-grade rule*: it changes a decision and
nets out against its cost. Examples (illustrative; the real weapons are the art task's):

| Weapon | Base | Trim | Trade |
| --- | --- | --- | --- |
| Shotgun | even spread | **Choke**: tight pattern, long reach | slower pump; punishes a miss |
| Shotgun | even spread | **Wide**: loose pattern, forgiving | short reach; hits fewer of a far pack |
| Submachine gun | steady | **Drum**: bigger magazine | slow reload; heavier; you commit |
| Rifle | steady | **Tracer**: shots paint the target for the whole team for 1.5 s | fewer rounds per reload; the team sees it, you do not hit harder |
| Flare gun | one bright flare | **Slow burn**: dimmer flare that lasts twice as long | covers a gap but holds the dead off less |
| Sidearm | quick draw | **Lamp-hand**: aims with the flashlight on | draws slower; light stays on you |

The **audit**: a seeded headless bot night with each weapon-trim pair (the kit's test mode already needs fixed
timestep and seeded randomness) must land within five percent of the base on rounds reached and points per round. A
trim outside that band is retuned before it ships. The same test is the standing guard against power creep.

### Concession Orders

The goals: three open at a time, like orders on the counter. Rules: no timers and no expiry; swapping an order is free
and unlimited (no pay-to-skip, no reroll currency); a player whose last three nights were solo is dealt no Together
orders, so a solo player is never locked out; none rewards a thing that hurts the team (nothing pays for being
downed; a rescue pays once per downed event).

| Pillar | Example order | Size |
| --- | --- | --- |
| Light | Keep three circuits powered through round 6 | medium |
| Light | Deliver a fuel can while the tank is under a quarter | short |
| Light | Finish a night without the generator ever browning out | long |
| Night | Reach round 8 | short |
| Night | Open every area before round 10 | medium |
| Together | Rescue three downed players in one night | medium |
| Together | Repair every board on a gate before the round ends | short |
| Together | Rescue five different players across nights | long |
| Craft | Earn 3,000 points with a weapon from the crane | short |
| Craft | Re-cut a weapon at the projector in three nights | medium |
| Place | Hold the booth during a round with the projector lit | medium |
| Place | Finish a round with the whole team on lit ground | medium |

| Size | Open for | XP | Stubs | Extra |
| --- | --- | --- | --- | --- |
| Short | 1-2 nights | 75 | 15 | - |
| Medium | 3-5 nights | 200 | 40 | - |
| Long | 10+ nights | 600 | 120 | a family that finishes grants a named cosmetic |

### Stubs and the Night Report

A night ends with the **Night Report**, a card of lines that mirror the pillars. XP is credited per line; stubs are one
per five XP. Kills are shown but pay nothing here (they already pay points), so nobody steals kills for XP.

| Line | Who | Pays | Cap per night | Pillar |
| --- | --- | --- | --- | --- |
| Rounds | team | 20 per round reached (10 per round past round 20) | - | A night that closes in |
| Lamps | team | 6 per circuit still powered at each round's end | 4 circuits x 20 rounds | Light is survival |
| Holdings | team | 30 per area opened and kept powered a full round | 6 areas | Light, the map |
| Rescues | each | 40 per revive, once per downed event | 5 | Together |
| Upkeep | each | 2 per board repaired, 15 per fuel can delivered under half a tank | 100 | Light, together |
| Orders | each | per the table above | - | - |
| Opening night | once ever | 300 | - | Onboarding |
| Mentor | each | +10% (to 100) when a player under Billing 10 is in the lot | 100 | Together |
| Solo | each | +10% night XP, standing in for the missing Rescues | - | Parity |

An *active* player counts toward a team line only for a round in which they earned points or did an act: standing in a
corner is not a way to be carried. Lines are server-computed from the round reports (see [data](#what-the-backend-stores)).

Anti-farm: every individual line is capped; there is a server-side XP-per-minute ceiling; long nights taper past round 20
rather than stop. A disconnect keeps what the rounds already banked.

**Rested XP:** time away accrues a pool (up to five nights' worth) that is paid out first on return. It replaces daily
login rewards: missing a day costs nothing and a long break is a bonus, not a loss.

### The Cast and the Marquee (cosmetic identity)

The setting is a 1958 drive-in, so the identity is the picture house itself. Every item is original to Deadnight;
period references below are the era's general look, not another game's content.

| Category | Examples | Where |
| --- | --- | --- |
| **Cast costumes** (per character) | usher's uniform and pillbox cap, carhop skates and apron, greaser jacket, varsity sweater, civil-defence warden helmet and armband, projectionist's coveralls, rubber-suit "creature from the screen" | stubs; milestones; orders |
| **Finishes** | chrome, two-tone paint (turquoise on cream), woodgrain panel, pinstripe, tin popcorn-box print, neon tube | stubs; mastery levels 2 and 10 |
| **Flashlight housings** | brass lantern, chrome torch, a hand-painted usher's torch | stubs |
| **Marquee** | the player's sign: a frame, its bulbs (colour and chase pattern) and a *Now Showing* word chosen from a card list | Billing levels; Encores |
| **Screen reels** | the film on the screen during a night (a B-movie poster, a creature feature, a newsreel), tinted but held to the same brightness | Billing 25; stubs |
| **Horn and emotes** | car horn, hand-jive, flashlight wave | stubs |
| **Lobby ambience** | the speaker-pole radio station in the menu, original tracks | stubs; milestones |

| Cosmetic rule | Why |
| --- | --- |
| No gameplay effect: same hit shapes, speed and flashlight beam as the base | A cosmetic must be safe to hand out freely |
| Light-emitting parts are decoration only and capped below a lamp's brightness | Light is survival; nobody may carry a better lamp |
| Every player keeps a fixed per-slot armband colour (four colours) whatever they wear | Teammates must be readable in the dark |
| The silhouette stays within the style bible: the big head, the mitts | The look holds together at game distance |
| Built as palette swaps of the family atlas where possible; mesh pieces within the style bible's budgets | The web build batches by material; a swap costs no draw call ([budgets](style.md#budgets-proposed-for-the-web)) |
| Name plates are chosen from word cards, not typed | Free text is a moderation job this game does not need |
| Reels never change the field's light level | The screen lights the front of the lot |

## Challenges: dailies, orders and milestones

Small, visible reasons to play a night a certain way, with no unlocks behind them yet (the foundation, issue #399:
the model, the counting, the save and the read API; the rewards below are placeholders). What the research behind it
found is in [Challenges](../research/challenges.md).

### Decision: daily challenges

The maintainer asked for daily challenges (2026-11-02, #399: "daily challenges and stuff to meet ... checkpoint
progress prompts in the UI during gameplay ... a really well thought out design ... modern and sleek, not
AI-ified") and then decided their shape: **dailies expire at each daily reset. No banking, no carry-over and no
streaks.** That changes rule 6, which used to say "nothing expires". The research
([Challenges](../research/challenges.md)) leaned the other way (Fortnite and Overwatch both moved toward progress
that carries over, and the CHI Play study found fear of missing out is one of three ways players take dailies); the
decision stands, and what keeps it from becoming a chore is in the table.

| Part of the decision | Rule |
| --- | --- |
| Dailies exist | Three a day, dealt from the date, the same for everybody |
| They expire | At the reset, finished or not: the board shows three new ones at zero. Nothing is banked, nothing carries over |
| No streak | Nothing counts consecutive days, or days played. Nothing is paid for opening the game |
| Small on purpose | One short, one medium, one long a day; the short one is under a night's work, so one night finishes something |
| Playing always counts | Every night advances everything it touches; a challenge adds a goal, it is never the only way to progress |
| Orders and milestones stay | Three orders at a time and the lifetime ladders have no timer and never expire; orders are the long goals |
| Nothing exists only on one date | A daily's reward (a placeholder today) is the same kind of thing every day |

### Families

| Family | Size | Refresh | Counts | Shown |
| --- | --- | --- | --- | --- |
| **Daily** | One short, one medium, one long a day (under a night to a few nights) | Expires at the player's midnight: the date picks the next three, at zero | From the moment it is on the board | Home panel and Challenges tab |
| **Order** (Concession Order) | Three open; short, medium or long (days to weeks) | Never. A finished order is replaced when the night ends; the player may swap any one at any time | Total or best night, per order | Challenges tab; the home panel shows the nearest to done |
| **Milestone** | A ladder of lifetime steps per stat (kills, nights, rounds, best round, headshots, boards, doors, grenade kills, melee kills, headliners, fuel cans, points) | Never; the rung is derived from the lifetime total | Lifetime | Challenges tab; a step reached shows in the night |

A challenge is a record in `game/gameplay/challenges/data/` (`dailies.json`, `orders.json`, `milestones.json`):
`id`, `text` (`{n}` is the target, so retuning a target retunes the words), `stat`, `target` (a milestone has `steps`),
`mode` (`total`, adding up across nights, or `night`, the best single night), `tier`, a `group` for dailies, a
`pillar` for orders and a placeholder `reward`. A test checks every file: unique ids, a stat the night counts, rising
steps, enough of every tier and group for a day to be varied.

### Refresh and the order draw

| Rule | Value | Why |
| --- | --- | --- |
| A day | Local midnight to local midnight (UTC where the platform gives no offset). The day is a whole number; the rotation is a function of it | A test can set any day; the same date gives the same dailies for friends in one call |
| The deal | One short, one medium, one long. Two of one group never share a day. A challenge dealt the day before is passed over | A day is varied; a returning player sees different things |
| Rotation memory | Worked out from the first day of a 30-day block, so a day needs no stored history; only a block's first day can repeat the day before | A pure function: no state, no drift between devices |
| Expiry | Every daily leaves at the reset, done or not; the new three start at zero, even one dealt again. A player away for a month sees three dailies and nothing else | No debt, no backlog, no catching up |
| Finished | A finished daily stays on the board, done, until the reset | The card shows done, once |
| Orders | Three, drawn from a seeded draw per account (`order_seed`, `order_draws`), not one finished lately. A swap redraws that slot and costs only its own progress. A finished order is replaced when the night is settled | No pay-to-skip; the pool is solo-safe by construction |
| Milestones | Lifetime totals; a best stat (the round reached) is a high-water mark | Facts stored, rungs derived |

### What a night counts

Counted from the events a client hears (`NightTally`), for every player in the night, solo and co-op by the same code.
A stat is a name; a challenge names one.

| Stat | From |
| --- | --- |
| `kills`, `kills:head` (head or weak zone), `kills:melee`, `kills:blast` (a grenade), `kills:boss` | `zombie_removed` (`cause` killed, the `killer_id`, `zone`, `melee`, `boss`) |
| `kills:weapon:<id>` | the same, with the killer's weapon: the last `weapon_equipped`, `shot_fired` or frame reading of that player. A blast has no weapon |
| `kills:type:<id>` | the same, by zombie type |
| `boards_repaired` | `board_repaired` |
| `doors_bought`, `buys`, `fuel_cans` | `purchase_made` (a refusal is `purchase_denied` and counts nothing) |
| `points_earned` | `points_changed` with a gain, without the starting purse |
| `rounds` | `round_ended`, for every player in the lot (down or not: playing always counts) |
| `round` (best) | `round_started`, `game_over` |
| `nights` | `game_over`, for every player still in the lot |

**Not counted yet, and no challenge asks for them** (a challenge the night cannot finish is a broken promise): rescues
(no teammate revive exists in the rules; a downed player gets up when the round ends, and `player_revived` names nobody
who helped), weapon mastery steps (mastery is not built), lighting goals that need the circuits' state (they are the
generator's, not a player's), and every "Together" order. Each is one stat and a data record the day its event exists.

### The read API

One small class, `ChallengeBoard` (`game/gameplay/challenges/challenge_board.gd`), is everything the main menu's home
panel and the Challenges tab (#397) read. It loads the save, deals today's dailies and saves what changed; it holds no
node.

| Call | Answers |
| --- | --- |
| `ChallengeBoard.open()` | The player's board (the save at `user://challenges.json`; a clock and catalogue can be passed for tests and captures) |
| `dailies()` | Today's three: `id`, `text`, `progress`, `target`, `fraction`, `done`, `tier`, `reward` |
| `orders()` | The open orders: the same keys plus `slot` and `pillar` |
| `milestones()` | Each ladder: `text` (the next step), `value`, `rung`, `rungs`, `target` (0 when done), `fraction` toward the next step, `done` |
| `seconds_to_refresh()`, `refresh_text()` | Time to the next dailies, "6 h 12 min" |
| `swap_order(slot)`, `refresh()`, signal `changed` | The one write the menu makes; `refresh()` when the screen is shown again |

### The save

Facts only, in the platform backend's envelope (`{revision, schemaVersion, data}`, [save format](../research/platform-backend.md#save-format)):
the day the dailies were dealt for, each daily's day and progress, each order's progress, the order seed and its
draw count, the lifetime totals by stat, how many dailies and orders were ever finished. Today it is the file
`user://challenges.json`; the backend slot later takes the same text. The rules: `schemaVersion` is 1; a newer
version is never read or overwritten (an old client cannot wipe progress); a damaged file is set aside as `.broken`
and play starts fresh; every number is small (a count or a seed under 2^31), so none needs the backend's string
rule for 64-bit values; a night saves at the end of every round and at the end of the night, so a quit loses at most
the round in progress. Only a night a person plays writes the save (bots, captures and tests have no board). **When
the server awards (rule 9)** the same `NightTally` and `ChallengeTracker` run on the game server, following every
player, and the client's board becomes a cache.

### The progress prompt in the night

A small checkpoint that says a challenge moved one step: a quarter mark (25, 50, 75, 100 percent) of a daily or an
order, or a milestone step reached. The rules, drawn from the [HUD](hud.md) and its [research](../research/hud.md):

- **Rare and quiet.** A target under 4 is only said when done (a quarter of 3 is no step). A jump over two marks says
  the highest. One prompt per challenge per moment; a daily, an order and a milestone crossing in the same instant are
  three prompts in a queue, not one crowded card.
- **A half-second read.** The name of the thing in at most six words, the count as the large part (`12 / 40`), and four
  punch-card dots, one more punched at each quarter. Nothing else: no reward text, no explanation (the Challenges tab explains).
- **One home.** It does not repeat a number the HUD already owns (points, round). Progress toward a challenge lives
  here and on the tab, nowhere else in the night.
- **Never over the crosshair or the round counter,** nor the prompt card, the gains, the feed, health or ammo. It
  sits in the free band at the middle of the screen's left edge, mirrors with a left-handed layout, and a test checks
  it against the HUD's measured parts at every canvas the HUD test uses.
- **Panels appear on change and leave.** In 0.25 s, held about 2.4 s, out 0.4 s (completions hold 3.2 s). With two or
  more waiting, holds shorten to 1.6 s so a burst of advances never queues up a minute of prompts. A completion is
  never dropped; the lowest quarter marks go first when more than three wait. Stale prompts (older than 20 s) are
  dropped, so one never describes something long gone.
- **Calm while it matters.** Nothing new starts while the player is down; the queue waits (and still goes stale).
- **A sound.** One soft cue: a short tick for a quarter mark, a rising pair for a finished challenge or a milestone,
  on the UI bus, quieter than a shot, made from a recipe in `tools/audio` (no generated voice).
- **Reduced motion and touch.** Reduced motion fades without sliding. The touch layout keeps clear of the fire
  and move buttons.
- **A setting.** `Challenge prompts`: all, completions and milestones only, or off. Nothing is hidden by default.

**The look** is the maintainer's choice for the main menu, "The program" (2026-11-02): a paper ticket, cream with dark ink,
notched like the HUD's cards, a perforated tear line down its left edge, progress as punch-card dots (a punched hole
is a quarter done), the finish a fifth mark: the last hole punched and the caption `FINISHED`. Two directions were
drawn for it first (a dark lit-sign card with a row of bulbs, and this ticket); the ticket was chosen so the night and
the menu read as one set of paper.

### The menu (issue #397)

The home panel shows the day's three dailies as three plain lines with their counts, the order nearest to done, and
"New dailies in 6 h 12 min" in small print. The Challenges tab has three groups (Today, Orders, Milestones) and a swap
on each order. Both read `ChallengeBoard` and nothing else. The menu's look is the maintainer's choice for the main
menu, "The program": paper tickets, with progress as punch-card dots; the night's prompt below matches it.

## How a fresh night stays fair

| Situation | Rule |
| --- | --- |
| Veteran and newcomer on the same night | Both start with the same points, fuel, lot and circuits. The veteran's extra is more *choice*; the starter program is always enough to win |
| The veteran's trims | The audit keeps them within five percent. A newcomer's starter weapon is not a worse weapon |
| Whose pool does the crane use | The player's own. Points, shop and crane are already per-player in the economy; pools are a property of the player, so nothing is shared that could be gamed |
| A lobby of friends in one Discord call | The common case: the Activity opens inside a voice channel and lists the connected participants ([Discord docs](https://docs.discord.com/developers/activities/development-guides/multiplayer-experience.md)). No queue sorts them |
| A public or fill-in lobby | Level is still not a signal. The host can tag the lobby *Newcomers welcome* (shown on the lobby card, nothing else changes) |
| A carried newcomer | Team lines need an *active* round; Rescues, Upkeep and Mentor pay the helpful veteran |
| A veteran whose friends are new | Mentor pays 10% extra, capped per night and per day, so nobody is punished for playing down and smurf accounts do not pay |
| A custom or modded lobby | Only a server instance the platform started with the canonical tuning (a ruleset hash) can award anything |
| Comparing results (leaderboards, if ever) | Only **Standard Nights** count: everyone uses the starter program and base trims. It also doubles as a way to play the plain game |
| Solo | Same unlock pace as a team ("Solo" row of the Night Report); orders drawn from the solo-safe pool |

## First ten hours: a tuning table

20 s break (the break is 5 s since #382, so each round is 15 s shorter and a night reaches the marks below a little
sooner; the table is not worked out again); a night has a 12 s intro and about two minutes in menus; the zombie count
follows the in-review rounds tuning; a three-player team splits points about 0.75 of a solo count each; average nights
reach the round shown. The numbers come from a small model, not play, and are expected to move.

Where the rest of the ladder falls, at about 780 XP a night: Billing 50 near hour 21; mastery 10 on the main weapon just
after hour 10; the second weapon around mastery 6 at hour 10. Ten hours should get a player to **every kind of choice
once**; the next twenty are cosmetics and mastery.

| --- | --- | --- | --- |

## What the backend stores

The platform backend ([issue #25](https://github.com/Ryubara/deadnight/issues/25)) is undecided between a custom
service, Nakama and Colyseus; this is the model, and it fits a relational table set or storage collections alike. The
rule is **store facts, derive the rest**: raw XP, ledgers and counters are stored; levels, tiers and "what is unlocked
by level" are computed from the tuning, so a retune never needs a migration.

| Record | Fields | Written by | Notes |
| --- | --- | --- | --- |
| `account` | id, Discord user id, display name copy, created, last seen, schema version | sign-in | Nothing else personal. Delete and export on request |
| `profile` | `xp` (raw), `stubs` (cached sum), `rested_xp`, `rested_at`, equipped costume, trims and name plate | server reports; client for equips | `stubs` can always be rebuilt from the ledger |
| `ledger` | account, delta kind (xp or stubs), amount, reason, match id, round index, time | server reports | Append only. The balance is its sum; support can see why |
| `unlock` | account, item id, source (billing, mastery, order, purchase, milestone), time | derived and idempotent | Re-evaluated when tuning changes, never removed |
| `mastery` | account, weapon id, raw mastery points | server reports | Level is derived |
| `order` | account, order id, slot, progress, state | server reports | Pool drawn from a seeded draw per account and slot |
| `night_log` | last 50 nights: match id, rounds, lines, time | server reports | For the history screen and for tuning telemetry |
| `match_report` | match id, round index, server version, ruleset hash, per-player facts, signature | game server | Idempotency key is (match id, round index) |

A **round report** is what the game server sends the backend at the end of every round (not only the night): the players
active in it and, for each, the facts that feed the Night Report (circuits powered, areas held, revives, repairs, fuel
cans, points by weapon, order events). Per-round reporting means a crash or disconnect still banks what was done, and a
retried report cannot double-pay.

| Question | Answer |
| --- | --- |
| Who can write progression? | Only a game server instance started by the platform; clients cannot post XP |
| What if the backend is down? | The night runs; reports queue on the game server and flush later |
| What if the game server crashes? | Rounds reported so far stand; the unfinished one is lost |
| Cheating? | Plausibility caps per line and an XP-per-minute ceiling; a ruleset hash that must match the canonical tuning |
| Retuning | Stored raw numbers, derived levels; an item added to a level is granted on next sign-in |
| Offline play | The client shows a cached read-only profile; nothing is written locally |
| Size | A profile is a few kilobytes; the ledger grows about 20 rows a night |
| Telemetry | Nights per day, level at day 7, quit round, trim pick and win rates, order completion time, unspent stub piles |

## Later: the weekly bill

A **Double Feature** is a weekly opt-in lobby type with two rule twists (for example, "the lights flicker" and
"double sprinters"), a stub bonus and one cosmetic *reel poster*. The bill changes weekly, nothing is lost by skipping
it, and every poster returns in the prize counter for stubs within a few weeks (the Helldivers lesson). It needs a
weekly operator task, so it ships only if the maintainer wants live operations.
